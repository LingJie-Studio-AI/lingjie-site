01 · 理念 PHILOSOPHY

大模型追逐广度，我们把一个领域做透

AGI 不只有「更大」这一条路。在无数真实场景里，人们需要的不是一个无所不知的庞然大物，而是一个把本职工作做到极致、成本低到可以忽略的小模型。

为什么是窄域？

通用大模型为了覆盖一切，付出了昂贵的代价：天量参数、集群训练、黑盒权重、难以复现。而真实世界的大多数需求，发生在少数窄域里——客服意图、票据抽取、领域问答、代码补全。

LingJie 的选择是：放弃广度，换取深度与自由。专为小模型设计创新架构，用窄域数据把每一个参数都用在该用的地方，把「降本增效」写进架构本身，而不是事后压缩。

「智能不必昂贵。当一个 64.87M 的模型就能把一类问题解决好，AGI 才真正属于普通人。」

工作原则

  1. 窄域优先

    先界定问题边界，再设计模型。一个模型只解决一类问题，把它做到该领域的上限。

  2. 成本即设计

    成本不是训练完再优化的指标，而是架构设计的第一约束：词表、注意力、专家数都为目标硬件让路。

  3. 开源即默认

    任何发布必须同时公开权重、脚本、代码与数据。做不到完整开源的成果，不发布。

常见疑问

窄域会不会把智能「做窄」了？
窄域限制的是任务范围，不是能力深度。把省下来的参数预算全部投入目标领域，窄域小模型在该领域的表现可以超过体量大它百倍的通用模型。多个窄域模型组合起来，同样能覆盖复杂业务。
直接用大模型蒸馏不就够了？
蒸馏是手段之一，但照搬大模型架构再压缩，会继承大量为「广度」付出的冗余。LingJie 从词表开始就为窄域重新设计，蒸馏只是训练流程中的一环，而不是全部。
训练数据从哪里来？
公开授权数据、合成课程数据与社区贡献数据三类来源，全部附带数据卡说明出处、清洗流程与配比。任何一份数据的来源都可以被追溯和审计。
02 · 架构 ARCHITECTURE

不是把大模型缩小，而是为小模型重新设计

HRLM v3.2 的六个组件，全部手写、不依赖 transformers 模型。选择任意模块查看设计细节，也可以用左右方向键切换。

    表中数据为冻结规格与实测值；训练/推理一致性以 11 项回归测试为准。

    设计目标

    参数预算64.874M（规格 64.863M，+0.02%）
    上下文训练 512 → 1024；注意力滑窗 4096
    训练硬件单张 RTX 4090（24GB）
    词表48,000（字节级 BPE，含 7 个特殊符）
    递归深度最多 3 轮，Router 逐 token 分配

    一次前向传播

    1. 因子化嵌入

      48000 × 192 的嵌入表上投影到 512 维，输入输出共用同一张表。

    2. 深度路由

      Router 逐 token 判断跑 1 / 2 / 3 轮，把算力分给真正难的 token。

    3. 10 个物理块

      7 个 GatedDeltaNet + 3 个 Mamba-2/滑窗注意力，残差 ×0.158。

    4. 绑定输出头

      RMSNorm → 下投影回 192 → 乘 √192 → 与嵌入表相乘。

    04 · 复现 REPRODUCE

    没有一键 CLI，但有完整的手动流程

    LingJie 没有 pip install lingjie，也没有 lingjie repro 这种命令。下面这套流程是我们在单卡 4090 上真实跑通的：从准备机器到拿到权重，每条命令都可以直接复制。预计 4~6 小时（含数据准备）。

    01

    准备机器

    单卡 RTX 4090（24GB）即可；数据打包阶段吃内存，建议 ≥32GB。系统 Ubuntu 22.04 + CUDA 12。

    # 检查环境
nvidia-smi
python3 -V          # 3.11
df -h /data         # 至少 20G 可用
    02

    装依赖

    只需要 PyTorch 与 tokenizers，不依赖 transformers 的模型实现。

    pip install torch --index-url https://download.pytorch.org/whl/cu128
pip install tokenizers numpy
    实测环境：torch 2.10.0+cu128 · tokenizers 0.23.x
    03

    拉代码

    仓库根目录下就是 Python 包（hrlm/），要在包的上一级运行，否则会 ModuleNotFoundError。

    git clone https://github.com/9178nekomc/LingJie-Code-v1-Beta.git /data/hrlm
cd /data          # 注意：不是 cd /data/hrlm
ls hrlm           # model.py train.py data.py ...
    04

    下载数据并核对

    预训练 1,184,107 条（1.3GB）、SFT 647,136 条（2.1GB）。先核对行数，别急着训。

    cd /data/data
curl -L -C - -o pretrain.jsonl "<预训练直链>"
curl -L -C - -o sft.jsonl ""
wc -l pretrain.jsonl sft.jsonl
# 1184107 pretrain.jsonl / 647136 sft.jsonl
    05

    数据准备：训分词器 + 打包

    这一步会训练 48000 词表的字节级 BPE，并把语料打包成 uint16 二进制，供训练零拷贝随机读。

    cd /data
python -m hrlm.prepare_data \
  --pretrain /data/data/pretrain.jsonl \
  --sft /data/data/sft.jsonl \
  --out /data/hrlm/artifacts
# => artifacts/tokenizer.json  （vocab 48000）
# => artifacts/pretrain.bin/.idx（368,975 条 / 3.78 亿 token）
# => artifacts/sft.bin/.idx
    中文必须先把汉字与数字孤立成预 token，否则整句会被当成一个"词"，BPE 训练会直接 OOM。
    06

    预训练（A/B/C 三阶段）

    1181 步 × 22 万 token = 2.6 亿 token；前 70% 用 seq 512，之后切 1024。每 250 步存一次 ckpt。

    cd /data
export HRLM_COMPILE_SCAN=1          # 编译扫描函数，7.1K -> 20.6K tok/s
export HRLM_CHUNK=32
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True

python -m hrlm.train --stage pretrain --arch hrlm \
  --tok artifacts/tokenizer.json --data artifacts/pretrain \
  --out runs/hrlm_pre --seq-len 512 --micro-batch 32 \
  --tokens-per-step 220000 --total-tokens 260000000 \
  --log-every 10 --probe-every 50 --save-every 250
    4090 实测约 11 秒/步，总时长 ≈ 3.6 小时。日志里会打印 loss / lr / gnorm / 三桶深度分布 / 残差 RMS。
    07

    SFT

    647,136 条 × 2 epoch，从预训练权重起。loss 只算 [思考]…[/回复] 段。

    python -m hrlm.train --stage sft --arch hrlm \
  --tok artifacts/tokenizer.json --data artifacts/sft \
  --out runs/hrlm_sft --seq-len 512 --sft-batch 64 --epochs 2 \
  --init runs/hrlm_pre/ckpt_latest.pt \
  --log-every 20 --probe-every 200 --save-every 2000
    08

    推理验证

    整段 prefill + 逐 token 递推，缓存按 [轮次][层] 保持。

    python -m hrlm.infer \
  --ckpt runs/hrlm_sft/ckpt_latest.pt \
  --tok artifacts/tokenizer.json \
  --prompt "一件衣服原价120元，打八折后售价是多少？"

    环境要求（实测）

    Python3.11

    踩过的坑（都会遇到）

    报 ModuleNotFoundError: No module named 'hrlm'
    工作目录错了。包在 /data/hrlm/，但必须 cd /data 再运行，让 hrlm 作为包被导入；在包内部运行时 sys.path 不包含上一级。
    上传的 .sh 一执行就报 set: pipefail: invalid option name
    Windows 上传的文件是 CRLF 换行，pipefail 后面粘了一个 \r。传完先跑一句 sed -i 's/\r$//' deploy/*.sh。
    分词器训练到一半被 Killed
    中文语料直接喂 ByteLevel BPE，整句会被当成一个"词"，词表统计把内存吃穿。必须先用正则把汉字与数字孤立成独立预 token（tokenizer.py 里的 _CJK）。
    CUDA out of memory 但显存看起来够
    3 轮递归 + 反向传播的激活是成倍放大的。开梯度检查点（默认已开）、把 micro-batch 降到 16、梯度累积补回 token 数；再加 PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True 减少碎片。
    训练速度只有 7K token/s
    扫描函数在 Python 循环里逐块调度，CPU 才是瓶颈。设 HRLM_COMPILE_SCAN=1 把两个扫描函数整图编译，实测 7.1K → 20.6K token/s，预训练时间从 15 小时降到 3.6 小时。
    下载中断了怎么办
    curl -C - 支持断点续传，重跑同一条命令会从断点继续。下完务必 wc -l 核对行数（1,184,107 / 647,136），少行说明没下完。

    摘要

    HRLM v3.2 是一个约 64.86M 参数的小型语言模型架构，面向中文日常对话 + 极简思维链（CoT）场景。核心思路是「小参数换深计算」：10 个物理块通过最多 3 次递归共享权重；以 SSM 为主干（7 个 GatedDeltaNet 块 + 3 个 Mamba-2 混合注意力块），注意力仅 3 层且滑动窗口 4K；Router 按 token 难度在 {1,2,3} 三档深度间分配算力，并以三阶段课程完成从全深度预热到硬路由收敛的过渡。训练与推理通过显式状态生命周期规范与 11 项回归测试保证严格等价。

    配套数据体系包括：预训练集 LingJie-P.T.-small（2.6 亿 token，四领域中文语料）与 SFT 集 LingJie-SFT-Cot-small（647,136 条纯中文带思维链指令数据），并强制设置同参数量、同 token、同 seq_len 的普通 Transformer 对照组以隔离收益来源。基于本规范训练的目标模型为 LingJie-Chat-v2-Beta。

    非目标：复杂推理、代码生成、多模态、超长上下文（>8K）、大规模并行训练，均不属于本架构的设计目标。

    核心设计取舍

    目标手段代价
    小参数换深计算10 个物理块 × 最多 3 次递归权重共享训练/推理状态管理复杂

    1.3 物理块布局

    0GDN 1GDN 2Mamba-2 + Attn 3GDN 4GDN 5Mamba-2 + Attn 6GDN 7GDN 8Mamba-2 + Attn 9GDN

    物理块 0–9：绿色为含注意力块（2/5/8），其余为纯 GatedDeltaNet。每块内部完成 Mixer + SwiGLU FFN 与两次标准残差（scale = 0.158）。

    1.4 组件精确定义

    因子化绑定嵌入（Stage 0）：唯一存储的嵌入表 48000×192，上投影 192→512、下投影 512→192，输出头复用同一张表。嵌入表初始化 N(0, 0.02)；上投影后加 1e-6 · normalize(h0)，防止门控骨干遇到精确零输入。

    PhysicalBlock 契约：块内部完成 Mixer、FFN、两次标准残差更新与状态更新；RecursiveCore 不再乘任何残差。

    class PhysicalBlock(nn.Module): def forward(self, x, state, token_mask): # x: [B,T,d_model] token_mask: [B,T,1] float 0/1 mixer_out, new_state = self.mixer(self.norm1(x), state, token_mask) x = x + token_mask * self.scale * mixer_out # 残差 1 ffn_out = self.ffn(self.norm2(x)) x = x + token_mask * self.scale * ffn_out # 残差 2 return x, new_state
    • self.scale = 0.158，所有块相同；token_mask 同时作用于残差和状态写入。
    • FFN 内部：SwiGLU(z) + 0.05（GateFloor）。

    GatedDeltaNet（块 0,1,3,4,6,7,9）：decay = 0.1 + 0.9 · sigmoid(w)，affine sigmoid 参数化，禁止 clamp；A_log 初始化 Uniform(log 1, log 16)；状态形状 [B, d_state, d_model]。状态更新必须按 token_mask 屏蔽写入：

    candidate = decay * state + delta * outer(v) new_state = torch.where(token_mask.bool(), candidate, state)

    Mamba-2 + Partial-RoPE Attention（块 2,5,8）：Mamba-2 分支同上屏蔽写入；注意力分支采用 QK-Norm（per-head RMSNorm），仅前 25% 头维度加 RoPE（head_dim=64 中前 16 维，其余 NoPE），滑动窗口 window=4096、KV cache 上限 4096。训练时 state=None，完整序列前向（因果掩码 + 窗口掩码）；推理时 state 为该轮该层的 KV cache。

    输出头（Stage 3，NoPE）：RMSNorm → down_proj → 乘 logit_scale（初值 √192，可学习）→ float() 后与 float() 绑定嵌入表相乘 → chunked cross entropy，避免物化 [B,T,V]，防 BF16 溢出。主体 NoPE，仅 3 个注意力块有部分 RoPE。

    1.5 递归路径与状态生命周期

    训练：阶段 A 走 run_recursive（强制 depth ≡ 3，与全激活等价）；阶段 B/C 走 compute_candidates——三个候选必须全 token 全激活前向，Router 只在最后加权时参与（B：soft Gumbel；C：straight-through）。禁止候选输出用 active_r = (depth > r)。

    推理：InferenceState 维护 [r][layer] 二维 ssm_state 与 kv_cache，跨 token 持久化，仅新序列开始时 reset()。禁止每生成一个 token 就重置状态——那会让训练/推理不等价。

    状态训练推理新序列
    states[i]（块内）每轮 [None]*10——
    ssm_state[r][i]—跨 token 持续，不重置reset() 清空
    kv_cache[r][i]—跨 token 持续，不重置reset() 清空
    • 状态屏蔽（强制）：非激活 token 的 SSM 状态原样保留，不衰减、不更新、不清空；禁止只在输出乘 token_mask 而不屏蔽状态写入。
    • 每块 states[i] 独立，维度/语义不同；递归注意力 KV 按轮隔离，禁止跨轮共享。
    • 深度有序：depth=2 执行第 1、2 轮，跳过第 3 轮；三轮不是独立二分类。

    1.6 Router 与三阶段课程

    RMSNorm（独立）→ Dropout(0.1) → Linear(512 → 3) → depth_logits [B,T,3]
    阶段步数范围占比策略τα（熵）β（均衡）
    A 全深度预热0–3550–30%depth ≡ 3，Router 只收辅助损失—0.030.01
    B 软路由退火355–82730–70%候选全前向 + soft Gumbel 加权2.0→1.00.030.01
    C 硬路由收敛827–1,18270–100%候选全前向 + straight-through1.00.010.003

    辅助损失：L_aux = α · L_entropy + β · L_balance。L_entropy 为 batch 内 depth 分布的熵（最大化，防塌缩）；L_balance 为三桶占比与均匀分布的 KL（阶段 C 减弱，让 Router 按难度分配）。SFT 阶段 α = β = 0.01，另加 CoT 边界辅助（权重 0.01 起）：对 CoT 结束 token 的 depth 分布向下偏置，观察 depth=1 桶占比上升且意图准确率不降。

    2.4 数据来源

    全部数据来自公开开源数据集，经清洗、转换、去重后整合而成。

    • 日常通用对话域：LCCC 大规模中文闲聊数据集（微博真实口语对话）、Mxode 中文通用推理数据集、Congliu 中文 R1 蒸馏指令集、OpenQA 中文开放问答数据集。
    • 基础数学推理域：School-Math-R1-Distil-Chinese 中小学数学推理集、公开中文基础数学 CoT 数据集。

    2.5 处理流水线

    1. 身份归一

      全量替换 50+ 第三方模型品牌标识，统一助手身份为 LingJie（凌界），system 提示词全局统一。

    2. 纯中文过滤

      汉字占比阈值校验，剔除外文为主与混合语言样本；繁简统一转换为简体中文。

    3. 格式统一

      多源异构 reasoning 字段统一收敛为 <think> 标签格式，对话结构标准化。

    4. 跨源去重

      基于 MinHash + LSH 的近重复去重，移除跨数据集重复与高度相似样本。

    5. 质量过滤

      剔除空内容、过短样本、违规敏感内容与低质量推理。

    6. 覆盖率对齐

      与配套预训练集做 bigram 覆盖率校验，整体覆盖率 99.6%，无领域外新增知识。

    2.6 局限性与许可

    • 数据均为模型蒸馏生成，推理质量受上游模型能力限制，部分样本可能存在推理冗余或细节瑕疵。
    • 以单轮指令对话为主，多轮长对话覆盖有限。
    • 仅含日常通用与基础数学内容，不包含医疗、法律、代码等垂直专业领域能力。
    • 无人工偏好标注与 RLHF 对齐数据，仅适用于基础 SFT 阶段。

    许可证：本数据集为开源数据整合加工产物，各子数据源遵循其原始开源许可证（MIT、Apache-2.0、CC 系列等）；使用者需自行遵守各原始数据集许可协议，整合包不对二次分发与商用做额外担保。数据集仅用于学术研究与模型开发，请勿用于违法违规场景。

    4.1 回归测试标准（起跑前必过）

    4.2 禁止事项（不得重犯）

    1. 禁止在 RecursiveCore 里写 x = x + active * scale * out。残差由 PhysicalBlock 内部完成，RecursiveCore 只负责轮次和状态生命周期。

    2. 禁止候选输出用 active_r = (depth > r)。阶段 B/C 候选必须全 token 全激活，Router 只在加权时参与。

    3. 禁止推理时每个 token 重置 ssm_state / kv_cache。状态按 (r, layer) 跨 token 持久，仅新序列 reset()。

    4. 禁止只在输出乘 token_mask。SSM 内部递推必须 torch.where 屏蔽状态写入。

    5. 禁止所有物理块共享一个 state 变量。每块 states[i] 独立，维度/语义不同。

    6. 禁止递归注意力 KV 跨轮共享。kv_cache[r][layer] 按轮隔离。

    7. 禁止用 clamp 实现 SSM decay。用 0.1 + 0.9*sigmoid(w)。

    8. 禁止把三轮递归当独立二分类。深度有序，depth=2 执行 1、2 轮，跳过第 3 轮。

    9. 禁止测试 1/5 在 BF16 下用统一 <1e-4。FP32 严格，BF16 按分布并检查是否随长度放大。

    10. 禁止在 v3.2 上增加模块或改参数量。修改需新版本 + 重跑全部回归测试。
